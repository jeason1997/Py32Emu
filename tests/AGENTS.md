# 测试与官方示例兼容规则

## 测试分层

- `unit/` 验证 CPU、总线、装配和外设寄存器边界。
- `firmware/` 保存由真实 Cortex-M0+ 工具链编译的最小验证固件，不放预编译产物。
- `integration/` 构建并运行 CLI、官方 SDK 示例和 Web；脚本必须 `set -eu`。
- `hardware/` 保存 DAPLink/OpenOCD 实机步骤，默认不得执行破坏性批量操作。
- 所有生成文件进入根 `build/`；测试脚本不得修改官方资料目录。

## 官方示例矩阵

- “官方全部示例通过”必须以 PY32F002A-STK `Example/` 的目录快照为基线，逐个记录：
  未评估、仅编译、运行通过、资料/例程缺陷、模拟器缺口。
- 每个通过项记录工程路径、构建源文件、运行参数、成功观察量和合理步数上限。
- 同一模块的一个示例不能代表其他示例；Polling、IT、DMA、低功耗和错误路径分别统计。
- 对双板示例应提供确定的虚拟对端；不能因默认返回值恰好满足断言就视为完整协议验证。
- 原版例程有缺陷时保留原始证据，并可另建“修正版验证”，但两者状态不得混为原版通过。
- 兼容百分比按矩阵总项数计算并写明公式，不以主观估计替代。

## 通过标准

- 编译成功不等于运行通过；步数上限不等于成功。
- 优先验证精确输出、内存、寄存器、IRQ 次数、回调副作用或外设事务。
- 测试不得通过读取固件符号名、特定 PC 或修改官方源码来让模拟器返回预设结果。
- 新发现的 CPU/外设缺陷先增加失败回归，再修复通用模型。
- 完整回归入口为 WSL `make clean && make test`；报告必须明确实际执行与未执行部分。
