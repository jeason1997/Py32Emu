# ARMv6-M 指令审查与 MIDI 音频复核

本轮结果：修复导致 MIDI 静音的 LDM 写回错误，并修复审查中确认的 PC 操作数、
特殊寄存器、故障中止、异常栈及反汇编问题。另修复 PWM 重建造成的额外尖刺和载波混叠。
没有修改外部 MIDI 工程的源码、ELF 或 MIDI 文件，也没有按固件 PC、符号或哈希添加执行特例。

这不是“全部 ARMv6-M 语义、全部编码或逐周期正确”的认证。以下明确列出已验证范围与剩余缺口。

## 依据与方法

- [Arm ARMv6-M Architecture Reference Manual，DDI 0419E](https://documentation-service.arm.com/static/5f8ff05ef86e16515cdbf826)：
  A5 编码分类、A6 指令语义、B1 异常状态与栈、B4 特殊寄存器访问。
- WSL GCC，C11，`-Wall -Wextra -Wpedantic`；独立边界回归与真实 Cortex-M0+ 汇编固件。
- [Unicorn](https://github.com/unicorn-engine/unicorn) 2.1.4，Cortex-M0 模式，固定种子
  `0x32f002a` 单步差分。比较 R0–R15、NZCV 与 4 KiB SRAM，不能用它证明周期、
  NVIC、外设或物理器件正确；差分发现的问题再按 Arm 手册核对。
- AddressSanitizer/UndefinedBehaviorSanitizer 检查 CPU 边界测试。

## 已修复并回归的缺陷

| 问题 | 修复 | 证据 |
|---|---|---|
| LDM 基址在列表中仍被地址写回覆盖 | 保留加载到基址寄存器的数据 | 2,040 种非空列表/基址组合；原版 MIDI 从静音恢复合成 |
| 高寄存器 ADD/MOV 读取 PC 为指令地址 +2 | 使用架构可见的 +4；PC 目标清最低位 | 单步差分、独立回归、真实汇编固件 |
| 写 SP 的高寄存器运算未保持对齐/别名 | 清除最低两位并同步活动栈 | 独立 MOV SP 回归，地址/SP 差分 |
| MRS 错误暴露 EPSR.T | EPSR 位通过 MRS 读为零 | PSR 别名、Handler/Thread 回归 |
| MSR 合法 PSR 别名被当成未定义指令 | 写 APSR 部分，忽略只读 IPSR/EPSR 部分 | 别名回归与单步差分 |
| MRS/MSR/CPS 缺少已有 nPRIV 状态的限制 | 限制特殊寄存器读写，Handler 写 CONTROL 仅忽略 SPSEL | 特权/非特权单元测试；不代表总线权限完整 |
| LDM/STM/PUSH/POP 故障后仍继续写回 | 立即中止当前指令；暂存 SP，成功后提交 | 第二次读取失败、POP PC 读取失败回归 |
| PUSH 内存访问按降序发生 | 按升序地址写入，成功后提交 SP | 总线记录回归和全部合法 PUSH 列表差分 |
| 异常栈未按 8 字节对齐 | 增加对齐填充，记录/恢复栈帧 xPSR[9] | MSP/PSP 在 4 模 8 地址入栈再返回 |
| Handler/异常返回的 SPSEL 与事件状态不完整 | Handler 使用 MSP；按 EXC_RETURN 恢复栈并置事件 | MSP/PSP 返回与事件回归 |
| 异常返回把非法 T=0 强制改为 1 | 保留恢复状态，下一次取指进入 HardFault | 非法 T 状态回归 |
| 后向分支左移负有符号数触发 C 未定义行为 | 有界乘二后转无符号偏移 | 后向分支及 UBSan |
| 反汇编器把 MRS/MSR/屏障当作两个独立半字 | 正确返回两半字长度；修复 BX/BLX 格式、字节访存掩码及负分支 UB | 独立格式/长度回归 |

## 仍需处理的缺口

以下是静态审查确认的功能缺口，未因本轮差分通过而标成已修复：

1. **高优先级：周期模型仍不完整。** 多数访存、多寄存器传送、分支和异常没有按
   Cortex-M0+ 逐类计费；MUL 固定 32 周期，尚未以该器件配置证明。Flash 等待状态、
   总线阶段和异常入口/退出开销未校准，不能声称实机 1:1。
2. **高优先级：SVC 的优先级提升。** CPU 直接进入 SVCall，没有完整核对当前执行优先级
   或 PRIMASK 下应升级 HardFault/锁死的条件。普通 SVC 固件通过不能代表这些边界正确。
3. **高优先级：系统异常挂起。** `system.c` 的 ICSR 写入位映射有错误：当前用 bit25
   置 SysTick、bit27 清 SysTick；规范对应为 bit26 置、bit25 清。NMI、PendSV 的软件
   挂起与服务路径也未完整实现。这是系统异常模型缺口，不是缺少某条算术指令。
4. **中优先级：权限覆盖。** 本轮限制了 MRS/MSR/CPS，但 PPB/SCS 等总线访问还没有完整
   根据 nPRIV 仲裁；不能将其用于权限隔离或安全性验证。
5. **中优先级：异常与保留编码。** 嵌套深度固定为 8；异常返回一致性、细分入栈/出栈
   故障与锁死策略仍需补齐。不可预测编码（如空列表、保留寄存器组合）尚未逐项统一策略。
6. **观察工具覆盖。** 反汇编器仍只覆盖部分助记符，合法指令显示 `.hword` 不等于 CPU
   无法执行。不能把反汇编文本覆盖率当成 CPU 指令覆盖率。

按当前 ARMv6-M 编码分类，没有新发现整类合法基本指令完全缺少解码入口；主要问题是已有
实现的边界语义与系统异常模型。`CBZ/CBNZ`、`IT/ITE`、硬件除法、独占访问等更高架构指令
不作为这个 Cortex-M0+ 目标的缺失项。

## MIDI 静音与电流声的不同原因

原始 ELF 只含播放器。歌曲区位于 `0x08002000`，格式为小端 32 位长度加原始或压缩歌曲。
缺少歌曲时停在 NO_SONG 分支；补入歌曲后，LDM 错误又破坏了 64 位等待计数，导致长期静音。

恢复发声后仍有额外噪声，不能把“WAV 非零”当作音质通过。对同一 300M 指令片段：

- 原引脚重建与占空比理想参考的残差 RMS 约 328，参考音乐 RMS 约 2,089。
- 旧电路层只观察指令末端电平，32 周期 MUL 内的窄脉冲会丢失。增加有序周期内引脚事件，
  在边沿处分割器件推进；残差 RMS 降到约 188。
- 矩形窗对 PWM 载波抑制不足，直接抽取造成混叠。默认改为连续三角窗，在采样前完成加权
  积分，三角窗总群延迟为一个 PCM 采样周期；与同窗理想参考的残差 RMS 约 9，相对参考约
  -47.3 dB。该对照不等于声学噪声或实物 SNR，滤波器也不是实际功放频响的测量模型。
- 新增回归：32 周期指令内完整脉冲不能丢失；快速载波的平均值与残差上限；滤波启动、
  群延迟和原始矩形窗模式。扬声器仍只读取引脚事件，不读取 SoC/固件寄存器。

当前定时事件只覆盖已有的 TIM1 CH3/CH4、PA0/PA1 AF13 路径。CPU 的寄存器事务仍为
指令粒度；其他引脚复用、复杂 PWM 模式与完整模拟电路没有因本轮修复而自动支持。

未连接实机进行本轮电气波形对照；也没有将此次第三方固件验证计入官方 SDK 兼容矩阵。

## 最终验证记录

- 将本轮全部源码复制到 `build/clean-audit/`，在该隔离副本执行 `make clean && make -j4 test`，
  单元测试、真实汇编固件、现有官方示例回归、Web 后端与 HTTP 测试通过；根工作区的音频证据保留。
- `build/sanitized/` 用 `-fsanitize=address,undefined -fno-sanitize-recover=all` 运行全部
  三组单元测试通过。默认 C11 警告选项下未发现新增编译警告。
- 最终默认 `-O2` 与本机画像优化构建：300M 条指令均为 361,616,754 模拟周期，生成
  332,235 个 44.1 kHz 样本（7.534 秒），两份 PCM 逐样本一致；优化构建离线约 4.31 秒。
  仅为该 MIDI 片段的单次测量，不能代表所有曲目或其他固件持续实时。
- 使用最终优化构建实际 `--audio` 播放并以 `RDPSink.monitor` 回录：133 个有效 50 ms
  窗口相关度中位数 1.0，无低于 0.9 的窗口，延迟变化 0 ms，两份 PCM 均无满幅削波。
  该结果证明这次短片段的数字输出链路，不证明用户声学端或全部曲目的主观音质。
- 原始电流声文件 `build/midi-current.wav`；最终源 PCM `build/midi-final.wav`；
  最终实时回录 `build/midi-live.wav`；回录分析 `build/midi-live-analysis/report.json`。
  生成文件不提交 Git，常规 `make clean` 会删除它们。
